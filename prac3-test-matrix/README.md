# Практическое занятие № 3 — Вариант А (Проверка дебита скважины)

**Участники:** Денис Низамов (№ 2), Алексей Каримов (№ 3)  
**Расчёт параметра:** $N = 2 + 3 = 5$; верхний предел $L = 100 + (5 \bmod 20) = 105\text{ м}^3/\text{сут}$.  
**Распределение ролей (этап 1):** Денис Низамов — Системный аналитик; Алексей Каримов — Разработчик.  
**Смена ролей (этап 2 — испытания и дефекты):** Алексей Каримов — Системный аналитик; Денис Низамов — Разработчик.

## 1. Измеримые критерии приёмки
* **A1:** Для `int` или `float` от `0` до `105` включительно вернуть `OK`.
* **A2:** Для числа за пределами интервала `[0; 105]` вернуть `RANGE`.
* **A3:** Для любого другого типа (включая `bool`) вернуть `TYPE` без исключений.
* **A4:** При 10 000 последовательных вызовах с чередованием `105` и `106` получить ровно `5000 OK` и `5000 RANGE`, а последующий вызов с допустимым значением возвращает `OK`.

## 2. Матрица тест-кейсов и протокол испытаний
* **Среда:** Python 3.11+
* **Объект проверки:** функция `check(value, limit)` из модуля `service.py` (`limit = 105`).
* **Предусловие:** импортирована функция `check`, установлено `L = 105`.
* **Общий шаг:** для A-01…A-07 выполнить одиночный вызов `check(вход, 105)`. Для A-08 и A-09 выполнить цикл чередующихся вызовов `105` и `106` заданной длины, затем сделать контрольный вызов.

## 3. Испытания после смены ролей

### 3.1. Карточка обнаруженного дефекта (Проверка чувствительности)
* **ID дефекта:** `DEF-01`
* **Версия ПО:** `service.py` (модифицированная: строгое неравенство `value < limit` вместо `value <= limit`).
* **Нарушенный критерий:** `A1` (верхняя граница интервала должна быть включена).
* **Вход и шаги:** вызвать `check(105, 105)` (кейс `A-02`), а также выполнить стресс-серии `A-08` и `A-09`.
* **Ожидание:** `OK` для значения `105`; `(5000, 5000, 'OK')` для `A-08`; `(5001, 5000, 'OK')` для `A-09`.
* **Факт:** `RANGE` для значения `105`; `(0, 10000, 'OK')` для `A-08`; `(0, 10001, 'RANGE')` для `A-09` (зафиксировано в `defect_protocol.txt`).
* **Повторный прогон:** после возврата оператора `<=` все 9 проверок снова завершились со статусом `PASS`.

### 3.2. Пояснение к испытанию на восстановление
Измеренная длительность одного прогона в Python не доказывает быстродействие на любом компьютере, поскольку время выполнения зависит от тактовой частоты и архитектуры процессора, текущей фоновой нагрузки ОС, версии интерпретатора и объёма доступной оперативной памяти.

## 4. Решение о приёмке
* **Проверяемая версия:** `service.py` (эталонная версия, с восстановленным нестрогим сравнением `<=`).
* **Статистика прогона:** запланировано — 9, выполнено — 9, **PASS — 9**, **FAIL — 0**, невыполненных — 0.
* **Вердикт:** **ПРИНЯТО**. Все измеримые критерии (`A1`–`A4`) подтверждены тестами, дефект `DEF-01` успешно локализован и исправлен, расхождений между ожиданием и фактом нет.

## 5. Ответы на контрольные вопросы
1. **Почему отказ для ошибочного ввода может быть PASS?**  
   Потому что задача негативного теста — убедиться, что система корректно распознаёт невалидные данные и возвращает предусмотренный контрактом код ошибки, а не «падает» или пропускает мусор дальше. Например, в строке **A-04** подаётся `-1`, мы ожидаем отказ `RANGE`, программа возвращает `RANGE` — поведение соответствует требованию, поэтому тест получает статус `PASS`.
2. **Какая ошибка останется незамеченной, если тестировать только середину интервала?**  
   Останутся незамеченными ошибки на границах диапазона (например, использование строгого неравенства `<` вместо `<=` или `>` вместо `>=`, из-за чего допустимые граничные значения `0` или `105` будут ошибочно отброшены как `RANGE`).
3. **Чем стресс-сценарий отличается от обычной проверки за границей и что показывает вызов после перегрузки?**  
   Обычная проверка оценивает логику ветвления на одном вызове, а стресс-сценарий проверяет устойчивость функции при многократном повторении операций подряд. Контрольный вызов после серии доказывает, что программа не накопила внутреннюю ошибку состояния (не «зависла» в режиме отказа) и готова штатно принимать валидные данные.
4. **Какие тесты заметили намеренный дефект и почему остальные могли остаться зелёными?**  
   Дефект заметили только тесты, использующие верхнюю границу `L = 105`: **A-02**, **A-08** и **A-09**. Остальные тесты (`A-01`, `A-03`–`A-07`) остались зелёными (`PASS`), потому что их входные данные (`0`, `0.5`, `-1`, `106`, `"15"`, `True`) не попадают в точку перелома логики `value == 105` и обрабатываются другими ветками кода.
